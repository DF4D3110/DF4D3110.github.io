关于 ES40

ES40 是一个开源的 AlphaServer ES40 模拟器，能够模拟基于 Alpha AXP 架构的硬件平台。它允许在现代 x86/x64 系统上运行专为 Alpha 架构编译的 Windows NT 4.0、Windows 2000 以及 OpenVMS 等操作系统。

ES40 模拟 Alpha AXP EV68CB 处理器及其他相关设备，目标是在功能上作为真实 ES40 服务器的替代方案。[citation:2]

项目信息：
  • 项目主页：https://github.com/ES40-Emu/es40/
  • 当前版本：0.77
  • 许可证：GNU General Public License v2
  • 支持的宿主机：Windows / Linux
  • 依赖：需要 npcap（网络支持）和 SDL（图形界面）。无网络版本可省略 npcap。[citation:11]
⚠️ 重要提示： 不同于 x86 模拟，Alpha AXP 模拟的性能开销较大，请确保宿主机有足够的 CPU 资源。同时，部分 Build 的 Windows Alpha 版本存在驱动兼容性问题，安装前请仔细阅读对应的注意事项。

准备工作

所需文件清单：

参考来源：ZXnet ES40 指南[citation:9]

  • ES40 模拟器主程序 (es40 Release.exe) — 可从 GitHub Releases 或 CI 构建获取
  • SRM 固件 (cl67srmrom.exe) — 来自 DEC/Compaq 固件包
  • AlphaBIOS 固件 (flash.rom + dpr.rom) — 由 ES40 自动生成或从固件更新 CD 获取
  • S3 显卡 BIOS (86c764x1.bin) — 来自 VGABIOS 项目或 ES40 配套文件
  • 可正常安装的 Windows Alpha 架构安装镜像
  • Alpha 系统固件更新 CD (v73.iso) — 用于更新 AlphaBIOS，非必需但推荐[citation:9]
  • 虚拟硬盘文件（建议 4GB，使用 qemu-img 或 es40-cfg.exe 创建）
推荐的目录结构： 
C:\apps\es40\
├── es40 Release.exe
├── es40-cfg.exe
├── es40.cfg
├── cl67srmrom.exe
├── rom\
│   ├── flash.rom
│   └── dpr.rom
├── disks\
│   ├── axp.vhd              (虚拟硬盘, 4GB)
│   ├── v73.iso              (Alpha 固件更新 CD)
│   └── install.iso          (Windows Alpha 安装镜像)
└── vga\
    └── 86c764x1.bin
关于 V73 ISO： 首次使用 ES40 建议先通过 v73.iso 更新固件。此步可确保 AlphaBIOS 版本与 Windows NT/2000 兼容，但并非必须。可使用 es40-cfg.exe 的光驱配置直接挂载该 ISO 并引导 [ES40]FWUPDATE.EXE 完成更新。[citation:9]

创建配置文件

使用 es40-cfg.exe 配置向导：

ES40 提供了独立的配置工具 es40-cfg.exe，运行后通过交互式问答自动生成 es40.cfg 文件。[citation:9]

运行方式：

在 ES40 目录下打开命令行，执行：

es40-cfg.exe

按照提示逐项回答即可生成配置文件。大部分问题直接按 Enter 接受默认值即可。

固件操作

两种固件：
  • SRM 固件：用于引导 OpenVMS、Tru64 UNIX 和 Linux。提示符为 P00>>>。
  • AlphaBIOS：用于引导 Windows NT/2000。提供图形化界面。

在 P00>>> 提示符下输入 arc 即可切换到 AlphaBIOS。[citation:3]

SRM 常用命令

命令 说明
arc 切换到 AlphaBIOS（用于引导 Windows）
show device 显示所有已连接的设备
show memory 显示内存信息
show cpu 显示 CPU 信息
boot 从默认设备引导
boot dka0 从特定设备引导（如 SCSI ID 0）

AlphaBIOS 常用操作

键盘快捷键：
  • F2 — 进入 AlphaBIOS Setup
  • F6 — 编辑选中的项目
  • F10 — 保存更改
  • Esc — 返回上一级菜单
AlphaBIOS 菜单结构：
  • Hard Disk Setup — 硬盘分区管理
  • CMOS Setup — 系统时间、启动选项设置
  • Utilities — 维护工具（含 Run Maintenance Program）
  • OS Selection Setup — 操作系统引导项管理

安装 Windows NT 4.0 Alpha

兼容性： Windows NT 4.0 Alpha 版本在 ES40 上 兼容性较好，是 Alpha AXP 模拟中最稳定的 Windows 版本。[citation:3]
安装步骤：

参考来源：BetaWiki 和 ZXnet 指南[citation:3][citation:9]

  1. 准备安装镜像：将 Windows NT 4.0 Alpha 的 ISO 镜像放入 disks\ 目录，修改 es40.cfg 中 disk0.1 的 file 指向该 ISO，或将光驱挂载为安装盘。
  2. 启动 ES40：运行 es40 Release.exe，在 P00>>> 提示符下输入 arc 进入 AlphaBIOS。
  3. 处理内存测试：首次启动会出现内存测试黑屏，按 Enter 继续。
  4. 设置系统时间与禁用内存测试：进入 AlphaBIOS Setup (F2) → CMOS Setup → 将日期改为 1998-01-01 → Advanced CMOS Setup (F6) → Power-up Memory Test 设为 Disabled → F10 保存。
  5. 创建分区：在 AlphaBIOS 主菜单选择 Hard Disk Setup → 按 F10 自动创建分区 → 按 Enter 确认。[citation:3]
  6. 启动安装程序：主菜单 → Utilities → Run Maintenance Program → 程序名输入 NT\SETUPLDR → 选择 CD: → 按 Enter。
  7. 执行安装：按照屏幕提示完成 Windows NT 4.0 安装。
  8. 首次启动：安装完成后，重启时再次进入 AlphaBIOS Setup，在 OS Selection Setup 中确认引导项指向正确的分区。
常见问题：
  • 如果安装程序提示找不到 hal.dll，请检查 ISO 是否为 Alpha 架构版本（而非 x86）。
  • 如果系统安装后无法引导，在 AlphaBIOS 中重新导入引导项（参考"引导修复"部分）。

安装 Windows 2000 64-bit (Build 2210)

⚠️ 高度实验性： Build 2210 是一个从未公开发布的 内部测试版，它：
  • 不是成品，甚至不是 Beta 版本
  • 无法运行常规的 32-bit Alpha 软件
  • NTFS 驱动存在 Bug，可能导致文件系统损坏
  • 仅在 ES40 特定配置下才能正常工作

此版本来自 Virtually Fun 博客记录的泄露恢复工作。[citation:4]

安装步骤：

此流程基于 Virtually Fun 博客的文档整理。[citation:4]

  1. 准备环境：将 axp64-2210-installable.iso 放入 disks\ 目录，修改 es40.cfg 中 disk0.1 指向该 ISO。
  2. 启动进入 AlphaBIOS：启动 ES40，在 P00>>> 输入 arc。
  3. 处理内存测试与 NVRAM：出现 Memory Error 按 Enter。出现 NVRAM bad 按 Enter（仅首次）。
  4. 设置系统时间：进入 AlphaBIOS Setup (F2) → CMOS Setup → 将日期改为 2000-03-10 → Advanced CMOS Setup (F6) → Power-up Memory Test 设为 Disabled → F10 保存。
  5. 创建分区：Hard Disk Setup → F10 自动创建分区 → Enter 确认。
    重要：D: 分区为 ARC 系统分区，切勿删除或格式化。
  6. 启动安装程序：Utilities → Run Maintenance Program → 程序名输入 AXP64\SETUPLDR → 选择 CD: → Enter。
    注：Build 2210 的 SETUPLDR 存在硬编码的 PALcode 文件名问题，可能需要特殊处理。[citation:4]
  7. 执行安装：按 F8 同意许可，选择 C: 分区进行安装（不要动 D: 分区）。可选择 NTFS 或 FAT 格式化（NTFS 有 Bug 风险）。
  8. 安装完成：安装结束时可能提示错误，点击 "否" 不重启。
  9. 修改启动参数：重启时按 F2 进入 AlphaBIOS → Utilities → OS Selection Setup → 选中启动项按 F6 编辑 → 将 OS Options 中的 /DEBUG 改为 /NODEBUG → F10 保存 → Esc 退出。
  10. 首次启动：从 AlphaBIOS 引导菜单选择 Windows 启动。如果提示运行 autochk（磁盘检查），务必取消以避免 NTFS 损坏。
关键提醒：
  • 每次启动都需要在 SRM 输入 arc 切换到 AlphaBIOS（Compaq 未正式支持 ES40 运行 Windows）。
  • 如遇 "Setup is starting Windows 2000" 卡住，请检查 SCSI 控制器设置或尝试更换 HAL。
  • NTFS 驱动 Bug 已知可能造成数据丢失，建议定期备份。

故障排除

卡在 "Setup is starting Windows 2000"

可能原因：

  • SCSI 控制器驱动不兼容
  • HAL 不兼容：在安装启动时按 F5 选择 "Standard PC" HAL
  • ISO 镜像损坏：重新下载并校验 MD5
0x0000007B 蓝屏（无法访问启动设备）

解决方法：

  • 检查 es40.cfg 中 pci0.2 的 SCSI 控制器配置是否正确
  • 确认虚拟硬盘已正确分区并格式化
  • 尝试在 AlphaBIOS 中重新导入引导项
AlphaBIOS 无法保存设置

检查 rom\flash.rom 和 rom\dpr.rom 文件是否完整且可写。如果文件损坏，从备份中恢复。

模拟速度极慢

优化建议：

  • 减少 memory.bits 的值（如 29 = 512MB）
  • 降低 cpu0.speed 的值（如 200M）
  • 确保宿主机有足够的 CPU 资源，关闭其他大型程序
"Could not open file" 错误

原因：ES40 无法找到指定的 ISO 或 VHD 文件。

解决方法：

  • 检查 es40.cfg 中文件路径是否正确（使用相对路径）
  • 确认文件名大小写与实际文件一致
  • 确认文件确实存在于指定目录

网络配置

说明： ES40 通过模拟 DEC 21143 网卡提供网络支持。Windows NT 4.0 和 Windows 2000 均自带此网卡的驱动程序。[citation:9]
配置步骤：

在运行 es40-cfg.exe 时，在提示 Would you like to add another PCI card to the system? 时选择 nic，然后按提示选择宿主机网络接口和 MAC 地址。[citation:9]

Windows 会自动识别为 "DEC DC21143" 网卡，安装驱动后即可使用网络。

注意事项：
  • 网络支持需要安装 npcap（或旧版 winpcap）[citation:9]
  • 如果下载的是 NN（无网络）版本，无法使用网络功能
  • 选择网络接口时，输入 ? 可查看所有可用接口列表

引导修复（AlphaBIOS）

适用场景： 当 Windows 引导项从 AlphaBIOS 启动菜单中丢失或损坏时，可通过以下步骤修复。
  1. 进入 AlphaBIOS Setup：启动时按 F2。
  2. 打开 OS Selection Setup：选择 Utilities → OS Selection Setup。
  3. 删除损坏的引导项：选中无效的引导项，按 Delete 删除。
  4. 创建新的引导项：按 F10 新建，填写以下信息：
字段 值（示例）
OS Name Windows NT 4.0 或 Windows 2000 64-bit
Boot Drive scsi(0)disk(0)rdisk(0)partition(2)（分区2为系统分区）
OS Path \WINNT（Windows 安装目录）
OS Options /NODEBUG（Windows 2000 64-bit 必须）
  1. 保存并退出：F10 保存 → Esc 退出 → 选择新引导项启动。
