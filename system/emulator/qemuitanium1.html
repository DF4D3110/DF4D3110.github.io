准备工作

概述：

Itanium 1（代号 Merced）是 Intel 第一代 IA64 处理器，与后续的 Itanium 2 在微架构和固件上有显著差异。本方案使用专门编译的 qemu-system-ia64-Itanium1.EXE 和专用固件 ia64-firmware-Itanium1.bin 来模拟 Itanium 1 环境。

与 Itanium 2 方案的关键差异：
  • QEMU 主程序： qemu-system-ia64-Itanium1.EXE（区别于 qemu-system-ia64.exe）
  • 固件文件： ia64-firmware-Itanium1.bin（区别于 ia64-firmware.bin）
  • CPU 类型： -cpu merced （必须指定）
  • 推荐内存： 1.5 GB (1536M)（Itanium 1 对内存管理有不同要求）
  • 显卡参数： 建议使用 -vga std（避免 ATI 驱动不兼容）
  • AHCI 支持： 早期版本（如 2462）需添加 ahci=off
目录结构示例： 
D:\QEMU-ITANIUM1\
├── qemu-system-ia64-Itanium1.EXE
├── qemu-img.exe
├── share\
│   └── vgabios-ati.bin (及其他固件)
├── Firmware\
│   └── ia64-firmware-Itanium1.bin
├── 2462.vhd
├── 2462.iso
├── 2462.bin (NVRAM)
├── 2600.vhd
├── 2600.bin (NVRAM)
├── ia64-2462.bat
└── ia64-2600.bat

启动命令

IA64 模拟性能较低，启动可能需要较长时间，请耐心等待。
Windows XP 64-Bit Edition Version 2002 (5.1.2600.0)： 
@echo off
setlocal
set SCRIPT_DIR=%~dp0
set SCRIPT_DIR=%SCRIPT_DIR:~0,-1%
"%SCRIPT_DIR%\Qemu_Windows\qemu-system-ia64-Itanium1.EXE" ^
-L "%SCRIPT_DIR%\Qemu_Windows\share" ^
-machine ia64-vpc,i8042=off,nvram=%SCRIPT_DIR%\2600.bin ^
-bios "%SCRIPT_DIR%\Qemu_Windows\Firmware\ia64-firmware-Itanium1.bin" ^
-accel tcg,thread=multi ^
-cpu merced ^
-smp 4 ^
-m 1536M ^
-net nic -net user,hostfwd=tcp::33890-:3389 ^
-drive file="%SCRIPT_DIR%\2600.vhd",format=vpc ^
-rtc base=2001-03-27,clock=vm ^
-display gtk
Windows Server 2003 (5.1.2462.0) — 含安装镜像： 
@echo off
setlocal
set SCRIPT_DIR=%~dp0
set SCRIPT_DIR=%SCRIPT_DIR:~0,-1%
"%SCRIPT_DIR%\Qemu_Windows\qemu-system-ia64-Itanium1.EXE" ^
-L "%SCRIPT_DIR%\Qemu_Windows\share" ^
-machine ia64-vpc,i8042=off,nvram=%SCRIPT_DIR%\2462.bin,ahci=off ^
-bios "%SCRIPT_DIR%\Qemu_Windows\Firmware\ia64-firmware-Itanium1.bin" ^
-accel tcg,thread=multi ^
-cpu merced ^
-smp 4 ^
-m 1536M ^
-net nic -net user,hostfwd=tcp::33894-:3389 ^
-drive file="%SCRIPT_DIR%\2462.vhd",format=vpc ^
-drive file="%SCRIPT_DIR%\2462.iso",media=cdrom,format=raw,readonly=on ^
-rtc base=2001-03-27,clock=vm ^
-vga std ^
-display gtk

参数说明（Itanium 1 特有）

参数 值 说明
⚠️ -cpu merced 必须指定！ 显式指定 CPU 类型为 Itanium 1 (Merced)。如果省略此参数，QEMU 会使用默认的 Itanium 2 指令集，导致模拟失败或系统崩溃。
-m 1536M 推荐使用 1.5 GB 内存，以避免更大内存出现的问题。
-vga std 建议添加，避免 ATI 显卡驱动在 Itanium 1 上引发蓝屏。
-machine ia64-vpc,...,ahci=off 早期系统（如 2462）需禁用 AHCI，否则无法识别磁盘。

RDP 远程桌面转发配置

功能说明：

与 Itanium 2 方案相同，Itanium 1 模拟也支持通过端口转发实现远程桌面连接。

端口转发参数： 
-net nic -net user,hostfwd=tcp::33890-:3389
  • 33890 — 宿主机端口（可自行修改，但需避免与系统服务冲突）
  • 3389 — 虚拟机内 RDP 服务的默认端口
端口冲突警告： 如果宿主机已开启 RDP 服务（即占用 3389 端口），则不能使用 3389 作为转发接口。请使用其他端口（如示例中的 33890 或 33894）。

Windows 系统内配置要求

  1. 启用远程桌面：
    • Windows XP 64-Bit Edition：右键“我的电脑” → 属性 → 远程 → 勾选“启用远程桌面”
    • Windows Server 2003：右键“我的电脑” → 属性 → 远程 → 勾选“启用远程桌面”
  2. 为当前用户设置密码： 确保登录账户有密码（空密码无法通过 RDP 认证）。
  3. 确认防火墙放行（通常不需要此步）： 
    netsh advfirewall firewall add rule name="RDP" dir=in action=allow protocol=TCP localport=3389

连接方法

  1. 启动 QEMU 并等待 Windows 完全启动。
  2. 在宿主机上打开远程桌面连接（mstsc）。
  3. 在“计算机”栏输入：localhost:33890（或您设置的其他宿主机端口）。
  4. 输入虚拟机的用户名和密码，即可连接。

注意事项

针对 5.1.2462.0 的特殊修复步骤：

Build 2462 在i386安装阶段结束后，系统无法进入其后的安装阶段。需要在虚拟磁盘上进行以下操作：

  1. 替换 EFI 分区引导文件： 将 EFI 分区的 ia64ldr.efi 替换为来自正式版（如 Build 2600）的版本。
  2. 替换系统驱动文件： 将系统分区 Windows\System32\drivers\npfs.sys 替换为来自正式版的版本。
所需文件下载： 包含替换所需的 ia64ldr.efi 和 npfs.sys 文件 下载 2462.zip →
显卡兼容性： 为避免 ATI 驱动不兼容导致蓝屏，强烈建议使用 -vga std 参数启动模拟器。
其他注意事项：
  • -cpu merced 必须指定： 这是 Itanium 1 模拟成功的必要条件。
  • NVRAM 文件： 不同 Build 使用独立的 NVRAM 文件（如 2462.bin、2600.bin），避免混淆。
  • RDP 端口： 不同实例使用不同端口（33890、33894）避免冲突。
  • RTC 时间： 建议设置为 2001-03-27（对应 Windows XP 开发周期）。

引导修复（详细流程）

参考来源：

本流程基于 HP Integrity BL860c Server Blade User Service Guide（第 88–91 页）中关于 Microsoft Windows 引导配置的描述，结合 IA64 平台的 EFI 特性整理。

当 Windows 启动项丢失或损坏时，可通过 EFI Shell 手动修复引导记录。Itanium 1 与 Itanium 2 的 EFI 环境基本一致，以下方法同样适用。

方法一：使用 nvrboot.efi 导入引导项

前提条件：
  • 系统已安装 Windows 且 \EFI\Microsoft\WINNT50\ 目录下存在 Boot00nn 文件。
  • 当前处于 EFI Shell 环境（从 EFI Boot Manager 选择 EFI Shell [Built-in] 进入）。
  • 已确认 Windows 所在的 EFI 系统分区（通常为 fs0: 或 fs2:）。
  1. 进入 EFI Shell： 启动 QEMU 后，在 EFI Boot Manager 界面选择 EFI Shell [Built-in]。
  2. 列出所有可引导设备： 在 EFI Shell 提示符下执行： 
    map -r
    找到 Windows 所在的 EFI 系统分区（通常标记为 fsX:，其中 X 为数字）。根据手册描述，EFI 系统分区是包含 \EFI\Microsoft\WINNT50\ 目录的分区。
  3. 切换到 Windows 所在的 EFI 分区： 
    fs2:
    （将 2 替换为实际分区号）
  4. 确认 Windows 引导文件存在： 
    ls EFI\Microsoft\WINNT50\
    应能看到类似 Boot0001、Boot0002 等文件。
  5. 启动 nvrboot.efi 工具： 
    msutil\nvrboot.efi
    根据手册，nvrboot.efi 位于 \MSUtil\ 目录下，用于管理 Windows 启动选项。
  6. 在 nvrboot.efi 交互菜单中导入引导项：
    • 输入 I（Import）导入引导选项。
    • 输入引导文件路径，例如：\EFI\Microsoft\WINNT50\Boot0001。
    • 按提示完成导入。导入成功后，工具会显示 Imported Boot Options from file 的确认信息。
  7. 验证引导项是否已添加： 
    bcfg boot dump
    检查输出中是否包含 Windows Server 2003 或 Windows XP 相关条目。
  8. （可选）设置 Windows 为默认启动项： 
    bcfg boot mv 2 1
    将 Windows 启动项移至首位（2 为当前编号，1 为目标位置）。
  9. 退出 nvrboot.efi： 输入 Q 退出工具。
  10. 重启系统： 
    reset
    系统重启后，EFI Boot Manager 应显示 Windows 启动选项。

方法二：使用 bcfg 命令手动添加引导项

说明：

如果 nvrboot.efi 不可用，或需要更精细的控制，可使用 EFI Shell 内置的 bcfg 命令手动管理引导项。根据手册，bcfg 是 EFI 系统中管理引导选项列表的标准命令。

  1. 进入 EFI Shell 并切换到 EFI 分区： 同方法一步骤 1-3。
  2. 查看当前引导项列表： 
    bcfg boot dump
    这会显示所有已配置的引导项及其编号。
  3. 添加新的引导项： 
    bcfg boot add 1 \EFI\Microsoft\WINNT50\ia64ldr.efi "Windows Server 2003"
    其中：
    • 1 — 引导项在列表中的位置（1 为第一位）
    • \EFI\Microsoft\WINNT50\ia64ldr.efi — 引导加载器的路径
    • "Windows Server 2003" — 在 EFI Boot Manager 中显示的名称
  4. 验证添加结果： 
    bcfg boot dump
    确认新添加的引导项已出现在列表中。
  5. 重启系统： reset
注意事项：
  • ia64ldr.efi 通常不是直接可执行文件，它需要配合 Boot00nn 配置文件使用。推荐优先使用 nvrboot.efi 方式导入。
  • 如果手动添加后无法引导，请检查 Boot00nn 文件是否存在于 \EFI\Microsoft\WINNT50\ 目录中。

方法三：使用 bcfg 调整引导顺序

  1. 查看当前引导项列表： bcfg boot dump，记下 Windows 引导项的编号。
  2. 将 Windows 引导项移至首位： 
    bcfg boot mv 3 1
    将编号为 3 的引导项移动到位置 1。
  3. 验证修改结果： 
    bcfg boot dump
  4. 重启系统： reset

方法四：配置 autoboot 自动启动

说明：

根据手册，autoboot 设置决定系统启动时是否自动加载引导项列表中的第一项。

  1. 启用自动启动（默认超时时间）： 
    autoboot on
  2. 设置自定义超时时间（秒）： 
    autoboot time 60
  3. 禁用自动启动： 
    autoboot off
    禁用后，系统每次都会停留在 EFI Boot Manager 界面等待用户选择。
  4. 重启系统： reset

备选方案：从 EFI Shell 手动引导 Windows

  1. 进入 EFI Shell 并切换到 EFI 分区： 同方法一步骤 1-3。
  2. 导航到 Windows 引导目录： 
    cd EFI\Microsoft\WINNT50
  3. 列出可用的引导文件： 
    ls
    确认存在 Boot00nn 文件。
  4. 执行引导加载器： 
    ia64ldr.efi
    这会手动启动 Windows 引导过程。

引导修复方法速查

方法 适用场景 关键命令/工具
方法一 Windows Boot Manager 丢失（推荐） \MSUtil\nvrboot.efi → 选择 I（Import）→ 输入 \EFI\Microsoft\WINNT50\Boot00nn
方法二 nvrboot.efi 不可用时 bcfg boot add # \EFI\Microsoft\WINNT50\ia64ldr.efi "Description"
方法三 修改默认启动项顺序 bcfg boot mv #a #b
方法四 配置自动启动 autoboot on/off、autoboot time 60
备选方案 临时手动引导 切换到 EFI 分区 → cd EFI\Microsoft\WINNT50 → ia64ldr.efi
通用注意事项：
  • 每次更换磁盘或重新安装系统后，都需要重新导入引导项。
  • 如果 EFI\Microsoft\WINNT50\ 目录为空，说明系统未正确安装，请重新安装。
  • 导入后如仍无法引导，检查 -drive 参数中的 if=ide 是否正确（Windows Server 2008 R2 必须使用 IDE，但 Itanium 1 早期系统通常使用 SCSI）。
  • 在 EFI Shell 中，文件系统编号（如 fs2:）可能每次启动后发生变化，建议使用 map -r 重新扫描后确认。

故障排除

问题 可能原因 解决方案
QEMU 无法启动 未指定 CPU 类型 添加 -cpu merced 参数
安装后无法进入 GUI Build 2462 特有 bug 替换 ia64ldr.efi 和 npfs.sys（见上方下载链接）
ATI 驱动蓝屏 显卡兼容性 添加 -vga std 参数
磁盘无法识别 AHCI 不兼容 添加 ahci=off 参数（早期版本）
模拟速度极慢 内存配置不当 使用 -m 1536M 而非 4G
NVRAM 冲突 多个版本共用 NVRAM 为每个版本使用独立的 xxx.bin
RDP 连接失败 端口冲突或防火墙 检查宿主机端口是否被占用，确认虚拟机内 RDP 已启用
