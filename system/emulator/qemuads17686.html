准备工作

本方案旨在为具有一定操作经验的朋友对 Windows Andromeda OS Build 17686.1003 与 17054.1000 在 QEMU 模拟器进行模拟。

关于 Andromeda OS： Andromeda 是 Windows Core OS 衍生版本，面向双屏移动设备（如 Surface Duo 原型机），基于 ARM32 (ARMv7) 架构，于 2018 年前后开发，后因未知原因取消，微软最终转向 Android。
需要准备：
  • 没有启动过的系统镜像，并自行刷写到一个 VHD 文件
  • QEMU（lzw_29107 下的项目）及 EDK2（修改者同人）

关于 EnableUefiSbTest.exe： 这是 Windows 驱动程序工具包 (WDK) 中的工具，用于为测试预生产 WHQL/WHCP 签名驱动程序而预配安全启动测试密钥。该工具会禁用安全启动、清除已有密钥、预配测试密钥并重新启用安全启动，为测试环境加载非生产签名驱动提供支持。
结论： 已确定发生问题的程序为 EnableWcosUefiSbTest.exe（用于测试安全启动的程序），定位到文件删除即可。

配置内核调试

QEMU 启动脚本（含调试管道）： 
set path=%~dp0
cd /d "D:\Emulator\QEMU v11.0.50-3c5e763 (ucrt64 dynamic build)"
qemu-system-arm ^
    -M virt,xhci=on,pci=on,force_el3=on,force_psci=on,highmem-mmio=off ^
    -cpu cortex-a15 ^
    -smp cores=2,threads=4 ^
    --accel tcg ^
    -bios "D:\Emulator\QEMU v11.0.50-3c5e763 (ucrt64 dynamic build)\QEMU_EFI_ArmVirtQemu_ARM_RELEASE.fd" ^
    -device VGA ^
    -device virtio-rng-pci ^
    -device usb-kbd ^
    -device usb-tablet ^
    -drive id=sys,if=none,file=D:\test.vhd ^
    -device usb-storage,drive=sys ^
    -rtc base=2018-08-13,clock=vm ^
    -m 2048 ^
    -serial pipe:debug ^
    -no-reboot
Windbg 连接配置：
  • Attach to kernel 内勾选 Pipe 和 Break on connection
  • 通道使用：\\.\pipe\debug
  • 其他保持默认
  • 只有 Windbg 连接到 QEMU 时，主程序才会继续运行
BCD 调试配置： 
bcdedit /store <path to BCD> /set {default} debug on
bcdedit /store <path to BCD> /set {default} debugtype serial
bcdedit /store <path to BCD> /set {default} debugport 1
bcdedit /store <path to BCD> /set {default} baudrate 115200

Build 10.0.17054.1000 特殊处理

Build 信息： 10.0.17054.1000.rs_apps_people.171205-1800 — 属于 Windows AndromedaOS 开发分支，同样为 ARM32 架构，此版本分区为传统wp分区，并不需要OSPool。
已知问题与处理流程：

Build 17054 与 Build 17686 存在类似问题，但处理方式更为复杂。需要按以下步骤操作才能正常启动：

  1. 删除问题文件： 与 Build 17686 类似，需要删除 EnableWcosUefiSbTest.exe 以保证系统能够正常启动。
  2. 覆盖 MainOS 分区： 将 Build 17054 的 MainOS 分区内容，单独覆盖到 Build 10.0.17110.1000.rs4_release.180223-1515 的 MainOS 分区中。此操作需要保留 17110 版本的其他非MainOS分区，仅替换MainOS分区的内容。
  3. 重设 Data 分区入口： 覆盖完成后，需要手动重设 Data 分区的入口点，确保系统能够正常读取部分内容并成功启动。
  4. 启动验证： 完成上述步骤后，系统应能正常启动。但请注意，部分 Appx 应用（如 Edge 浏览器）可能会运行异常或不存在。
关于内核调试的建议：

由于 Build 17054 属于开发中版本，系统功能尚不稳定。在测试过程中，因系统内部错误导致崩溃的可能性较高。建议在测试该 Build 时 始终启用内核调试，以便在发生崩溃时能够及时捕获错误信息进行分析。

操作要点总结：
  • 删除 EnableWcosUefiSbTest.exe（位于 MainOS 分区）
  • 将 17054 的 MainOS 覆盖到 17110 的 MainOS（注意：是 17054 → 17110，方向不可反）
  • 重设 Data 分区入口
  • 建议全程启用内核调试

由于该流程涉及手动文件替换和引导配置，操作前请充分阅读该教程的内容。

设备模拟问题 (xHCI)

xHCI 驱动兼容性： 由于 ARM 系统在 Build 18362 之前的系统自带 xHCI 驱动存在问题，如果需要使用 xHCI 进行输入，需要将MainOS分区中的 \Windows\System32\drivers\Ucx01000.sys 替换为 Build 18362 及之后版本。

虽然直接 Patch 也可以，但为避免签名问题，建议使用替换方式。

关于 Ucx01000.sys： 这是 Windows 系统提供的 USB 主机控制器扩展驱动 (UCX)，位于 Windows\System32\drivers\Ucx01000.sys。它作为主控制器驱动和 USB 集线器驱动之间的抽象层，负责将 USB 请求排队到底层主控制器驱动。如果 xHCI 硬件不完全符合规范或存在兼容性问题，可能需要替换此驱动或编写自定义主控制器驱动。
SD 设备替代方案：
  • 使用 SD 设备也可以，需要将 VHD 容量改为 32GB。
  • 如果设置 xhci=off，此时默认使用 EHCI，但不可进行 USB 启动。
  • xHCI 必须替换上述 .sys 文件后才能进行 USB 启动并使用 USB 输入。

启动参数参考

作者使用 xHCI + USB 启动： 已替换 Ucx01000.sys，完整启动脚本如下。 
set path=%~dp0
cd /d "D:\Emulator\QEMU v11.0.50-3c5e763 (ucrt64 dynamic build)"
qemu-system-arm ^
    -M virt,xhci=on,pci=on,force_el3=on,force_psci=on,highmem-mmio=off ^
    -cpu cortex-a15 ^
    -smp cores=2,threads=4 ^
    --accel tcg ^
    -bios "D:\Emulator\QEMU v11.0.50-3c5e763 (ucrt64 dynamic build)\QEMU_EFI_ArmVirtQemu_ARM_RELEASE.fd" ^
    -device VGA ^
    -device virtio-rng-pci ^
    -device usb-kbd ^
    -device usb-tablet ^
    -drive id=sys,if=none,file=D:\test.vhd ^
    -device usb-storage,drive=sys ^
    -rtc base=2018-08-13,clock=vm ^
    -m 2048 ^
    -serial pipe:debug ^
    -no-reboot
关于 RTC 时间参数： -rtc base=2018-08-13 用于绕过 Windows 预览版的时间炸弹。Build 17686 作为 2018 年 6 月发布的预览版，其时间限制通常从编译日期开始计算，将此参数设为 2018-08-13 可确保系统在 OOBE 阶段不会因时间过期而强制重启。
SD 卡启动替代： 如果需要 SD 启动，将 -device usb-storage,drive=sys 改为 -device sd-card,drive=sys 即可。

备注与致谢

性能与稳定性：
  • 系统模拟可能偏慢，需要耐心等待。
  • 通过 OOBE 后不会重启，会直接进入系统。
  • 重启后第二次启动不一定能够进入系统，由于当前还在测试探索，不再叙述过多缘由。
Andromeda 与 Windows Core OS： Andromeda OS 基于 Windows Core OS (WCOS) 构建，WCOS 是微软内部旨在提供模块化通用操作系统基础的努力。WCOS 移除了传统桌面 Windows 的大量遗留功能，采用基于 DirectX 和 UWP/WinUI 的新 GUI 栈。Andromeda 项目的取消最终导致 Surface Duo 转向 Android 系统。
