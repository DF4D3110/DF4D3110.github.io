Windows System Kit (WSK) 构建指南

使用 WSK 生成自定义 Factory OS / Windows 10X 映像 WSK Factory OS ⚠️ 仅供研究
说明：
1. 本指南基于 Windows System Kit (WSK) 官方文档与社区实践整理；
2. 涵盖 Build 18941、18985、22000 等多个版本；
3. 所有操作仅供学习研究，请遵守相关许可协议。
4. 该教程仅供新手初次熟悉流程，如果你本身能力已经很强，那么这个教程对你来说没有任何意义，你应该去 Microsoft 官网进修而不是在这里。

准备工作

宿主机要求：
  • Windows 10 或 Windows 11 主机系统
  • 完整的 WSK ISO（Build 18941、18985 或 22000）
  • 至少 50 GB 可用磁盘空间（建议 SSD）
外部下载：

此处仅提供 Build 22000 的官方下载参考，其他版本请读者自行寻找：

  • Microsoft Windows System Kit (WSK) for Windows Factory OS | Microsoft Learn
重要提示： 如果你已经准备好了所需的 ISO，请将其装载（或解压），并确保文件结构完整。假设装载位点为 E:\。
ISO 光盘结构（示例，Build 22000）：

打开 Windows System Kit 环境

  1. 导航到分配给已装载的 WSK ISO 的驱动器根目录（例如 E:\）。
  2. 右键单击 SetImagGenEnv.cmd，选择“以管理员身份运行”。
预期输出：

创建工厂 OS 工作区

工作区说明：

工作区是一个工作目录，它有助于整理创建工厂 OS 映像所需的应用、驱动程序和其他资产。

基本命令： 
PrepWSKWorkspace C:\FactoryWorkSpace -Product FactoryOS
创建虚拟机映像（添加 -VM 参数）： 
PrepWSKWorkspace C:\FactoryWorkSpace -Product FactoryOS -VM

添加 -VM 参数后，最终映像将是一个 .vhdx 文件 (UEFI)。生成 VM 映像时，不会生成 FFU。

PrepWSKWorkspace 语法

PrepWSKWorkspace {-Destination} <Path> {-Product [productname]}
{-ProductConfiguration [Development|Manufacturing|ramboot_pre_oobe|ramboot_post_oobe]}
{-Architecture [AMD64|x86|Arm|Arm64]} {-VM} {-Overwrite [YES|NO|PROMPT]}
{-AdditionalLanguages [lang-lang,lang-lang]} {DefaultLanguage [default-language]}
参数 说明
-Destination（必需） 目标目录，例如 C:\Workspace。如果此目录不存在，则脚本会创建它。可以选择现有的工作区文件夹。
可能需要在电脑上启用长文件路径，具体取决于工作区的存储位置。
-Product（必需） 指定工作区支持的产品。
选项：
• FactoryOS
• HubOS（仅限 18941）
• wcoscdg（18941/18985，即 Windows 10X）
• wcosref（需手动复制 FM 构建）
-ProductConfiguration 配置 PrepWSKWorkspace 创建的 OEMInput 文件。值区分大小写。
选项：
• Development：用于启动和测试（默认）
• Manufacturing：减少磁盘占用量和高性能电源管理模式（适用于 Factory OS）
• win32_manufacturing / win32_development：配置可在容器中运行诊断 Win32 应用的 Factory OS 版本
-Architecture [AMD64|x86|Arm|Arm64] 要构建的设备体系结构。默认体系结构为 AMD64。
注意：ARM/ARM64 版本需要特定的设备布局相关包，此处仅以 x86/AMD64 为例说明。
-VM 用于生成虚拟机映像。添加此参数时，最终映像将是一个 .vhdx 文件 (UEFI)。生成 VM 映像时，不会生成 FFU。
-Overwrite:[Yes|No|Prompt] 控制是否覆盖现有工作区。
• Yes：覆盖目标文件夹中的任何冲突文件
• No：不覆盖，仅复制新文件
• Prompt：覆盖前询问（默认）
-AdditionalLanguages [lang-lang] 用于将语言包和可供用户安装的功能添加到 OEMInput 文件。使用语言-区域性格式指定语言，例如 de-de、fr-ca 等。
-DefaultLanguage [default-language] 指定映像中的默认语言。映像只能指定一种默认语言。使用语言-区域性格式指定语言，确保默认语言是 OEMInput 文件中包含的语言。
注： -Product 参数在现有 WSK 中均可填入 FactoryOS。
18941 存在 HubOS 这一 SKU。
18941 和 18985 存在 wcoscdg（即 Windows 10X 的一个 SKU）。
wcosref 目前未找到有效方案进行操作，需要手动复制 FM 进行手动构建。

生成映像

第二步结束后会生成 XML 文件，例如： 
OEMInput file E:\FactoryWorkSpace\FactoryOS_Win32_Development_AMD64_UEFI_SpacesGPT_Hardware.xml created.
Successfully saved the Configuration file at E:\FactoryWorkSpace\FactoryOS_Win32_Development_AMD64_UEFI_SpacesGPT_Hardware_Configuration.xml.
Success!
E:\FactoryWorkSpace>

这里 FactoryOS_Win32_Development_AMD64_UEFI_SpacesGPT_Hardware_Configuration.xml 就是下一步需要的 XML。

构建命令： 
BuildWSKImage %WSKWorkspaceRoot%\FactoryOS_Development_AMD64_UEFI_SpacesGPT_Hardware.xml

即 BuildWSKImage 后面的文件即为上一步输出的 XML 的绝对路径，回车后即开始构建。

构建过程耗时较长，请耐心等待。建议在 SSD 上进行操作以获得更好的性能。

多语言支持与常见问题

多语言支持说明：

尽管 WSK 中的 FactoryOS 程序包提供了三种显示语言支持（en-US、zh-CN、zh-TW），但由于发布时未经充分测试，无法使用内置工具自动完成语言相关设置。

例如，在使用 PrepWSKWorkSpace 脚本创建 OEMInput.xml 时，如果指定添加语言或设置默认语言的参数，会出现错误提示：不支持修改非 ModernPC SKU 的语言。

解决方案：手动修改 OEMInput.xml

推荐方法：

直接手动修改 OEMInput.xml 的 <Languages> 元素：

<Languages>
    <Language>en-US</Language>
    <Language Default="true">zh-CN</Language>
    <Language>zh-TW</Language>
</Languages>
  • 添加语言：添加 <Language>zh-CN</Language> 或 <Language>zh-TW</Language>。
  • 设置默认语言：添加属性 Default="true"。
重要注意事项：
  • 默认语言唯一性： 标记了 Default="true" 的语言只能有一个，否则会在制作时抛出异常。可以删除多余的 Default 属性或将其设为 false。
  • en-US 必须保留： 如果直接修改原始 en-US 部分来改变语言，制作时 ImageApp 将会警告：必须包含 en-US 语言，并且会自动增加该语言。理论上可以通过修改内置工具绕过此要求。
  • 大小写敏感： ImageApp 判断文件是否存在的部分方法会区分大小写，因此 en-us 与 en-US 可能会影响制作结果。
常见错误与解决方法：
  • “找不到指定的文件” — 如果当前系统版本高于 WSK 版本，可能出现该异常。可尝试将 WSK 文件复制到其他可写位置再修改（直接修改 ISO 本身较为复杂）。
  • 无法挂载/卸载 UpdateOS — 同上，可能与系统版本不兼容有关。
  • 无法检测存储池版本 / 报错“尝试读取或写入受保护的内存” — 通常由环境不兼容引起，建议在匹配的 Windows 版本上运行。
ARM / ARM64 体系结构：

与 AMD64 不同，官方未提供通用设备包，需要自行创建设备布局相关包。

容器支持： 尚未进行测试。已知 ARM 体系结构不提供容器支持。

RamBoot 支持：

完整系统的 RamBoot 支持尚未进行测试。不同于从 UpdateOS.wim 启动的方式。
