准备工作

QEMU 下载：
  • x86_64 版本（ZZPPAP 编译）： QEMU-SYSTEM-IA64_x86_64.7z 适用于 x86_64 宿主机
  • AArch64 版本（ZZPPAP 编译）： QEMU-SYSTEM-IA64_AARCH64.7z ⚠️ 仅限 ARM64 宿主机
  • x86_64 版本（DF4D3110 编译）： Qemu_Windows_2607232243.zip 包含完整依赖，需要 -L 参数额外指定 vgabios-ati.bin 等文件所在路径

ZZPPAP 编译版本由 ZZPPAP 编译，感谢其贡献；DF4D3110 编译版本由本人编译。

重要提示： 下载的压缩包已包含 qemu-system-ia64.EXE 但是缺少部分文件，可用ARM32模拟方案的qemu进行覆盖(原有文件保留)来实现运行。
⚠️ 警告： SKI 仿真器中已经启动到桌面的系统 不可直接迁移到 QEMU 运行，否则会导致系统启动崩溃。如需在 QEMU 中运行，请使用 QEMU 环境下的全新安装。
本机文件列表（示例）：
  • qemu-system-ia64.exe — 主程序（约 47.3 MB）
  • ia64-firmware.bin — IA64 UEFI 固件（约 810 KB）
  • qemu-img.exe — 磁盘映像工具（约 12.9 MB）
  • SDL2.dll 及众多 lib*.dll — 运行时依赖库
目录结构示例： 
D:\QEMU-SYSTEM-IA64_x86_64\
├── qemu-system-ia64.exe
├── qemu-img.exe
├── ia64-firmware.bin
├── SDL2.dll
├── lib*.dll          （大量依赖库）
├── lib\              （额外库目录）
├── share\            （共享资源）
└── run.bat           （可选启动脚本）

解压后直接将 ia64-firmware.bin 和系统 ISO 放在同一目录即可。

启动命令

IA64 模拟性能较低，启动可能需要较长时间，请耐心等待。
通用启动命令（分行便于查看参数）： 
qemu-system-ia64.exe ^
    -machine ia64-vpc,i8042=off,nvram=nvram.bin ^
    -bios ia64-firmware.bin ^
    -drive file="install.iso",media=cdrom,format=raw,readonly=on ^
    -accel tcg,thread=multi ^
    -smp 4 ^
    -m 4G ^
    -nic user,model=e1000 ^
    -drive file=ia64.vhd,format=vpc ^
    -display gtk
Windows Server 2008 R2 推荐命令：

针对 Windows Server 2008 R2 (Build 7000)，必须添加 if=ide 参数将磁盘接口设置为 IDE，否则系统会蓝屏。RTC 时间参数为可选，仅在遇到时间相关校验问题时使用。

qemu-system-ia64.exe ^
    -machine ia64-vpc,i8042=off,nvram=nvram.bin ^
    -bios ia64-firmware.bin ^
    -accel tcg,thread=multi ^
    -smp 4 ^
    -m 4G ^
    -nic user,model=e1000 ^
    -drive file=ia64.vhd,if=ide,format=vpc ^
    -drive file="install.iso",media=cdrom,format=raw,readonly=on ^
    -display gtk
可选 RTC 参数（仅在需要时添加）：

如遇到与系统激活或时间校验相关的问题（例如“系统时间异常”提示），可在命令末尾添加：

-rtc base=2008-12-27,clock=vm
简化版命令（便于复制）： 
qemu-system-ia64.exe -machine ia64-vpc,i8042=off,nvram=nvram.bin -bios ia64-firmware.bin -drive file="install.iso",media=cdrom,format=raw,readonly=on -accel tcg,thread=multi -smp 4 -m 4G -nic user,model=e1000 -drive file=ia64.vhd,format=vpc -display gtk

参数说明

参数 值 说明
-machine ia64-vpc,i8042=off,nvram=nvram.bin 指定机器类型为 ia64-vpc，禁用 i8042 键盘控制器，指定 NVRAM 文件
-bios ia64-firmware.bin 指定 IA64 UEFI 固件文件路径（与 qemu-system-ia64.exe 同目录）
-drive (CD-ROM) file="install.iso",media=cdrom,format=raw,readonly=on 挂载 ISO 镜像为虚拟光驱，只读
-accel tcg,thread=multi 使用 TCG 软件模拟，启用多线程加速
-smp 4 分配 4 个 CPU 核心（可根据实际调整）
-m 4G 分配 4GB 内存
-nic user,model=e1000 使用用户模式网络，模拟 Intel e1000 网卡
-drive (HDD) file=ia64.vhd,format=vpc 或 file=ia64.vhd,if=ide,format=vpc 挂载虚拟硬盘（VHD 格式）。
• 默认（无 if=ide）： 磁盘为 SCSI 设备，适用于 Windows Server 2003 等旧系统。
• 添加 if=ide： 磁盘为 IDE 设备，Windows Server 2008 R2 必须使用此参数，否则系统将无法识别启动盘导致 0x0000007B 蓝屏。
-rtc base=2008-12-27,clock=vm（可选） （可选参数） 设置 RTC 基准时间，仅在遇到时间校验相关问题时使用。一般情况下不需要添加。
-display gtk 使用 GTK 图形界面显示

虚拟磁盘创建

使用 qemu-img.exe 创建 VHD 格式磁盘： 
qemu-img.exe create -f vpc ia64.vhd 20G
说明：
  • -f vpc — 指定 VHD 格式（Virtual PC 兼容）
  • ia64.vhd — 磁盘文件路径（与 qemu-system-ia64.exe 同目录）
  • 20G — 磁盘大小（可根据需要调整，如 40G）
  • 特别提醒： 创建完成后，在启动命令中根据需要决定是否添加 if=ide。对于 Windows Server 2008 R2，必须使用 if=ide。

Windows Server 2008 R2 特别说明

关键要点：
  • 必须使用 IDE 磁盘接口： Windows Server 2008 R2 的 IA64 版本默认 SCSI 驱动在 QEMU 环境下存在兼容性问题。必须在 -drive 参数中明确指定 if=ide，即 -drive file=ia64.vhd,if=ide,format=vpc。如果省略 if=ide，磁盘将被识别为 SCSI 设备，系统启动时会提示无法找到启动设备 (0x0000007B 蓝屏)。
  • RTC 时间为可选： -rtc base=2008-12-27,clock=vm 参数不是必须的。仅在系统提示时间相关错误（如“系统时间异常”或激活校验失败）时，才需要添加此参数。大多数情况下，无需设置 RTC 即可正常启动和安装。
  • ISO 文件确认： 请确保使用的 ISO 镜像为 IA64 架构 专用版本，x86/x64 版本无法在此模拟环境中运行。
启动参数核对清单（Windows Server 2008 R2）：
  • ✅ -drive file=xxx.vhd,if=ide,format=vpc （必需，IDE 接口）
  • ✅ -machine ia64-vpc,i8042=off,nvram=xxx.bin （正确机器类型）
  • ✅ -bios ia64-firmware.bin （正确固件路径）
  • ❓ -rtc base=2008-12-27,clock=vm （可选，仅在需要时添加）

Windows Longhorn 测试记录

测试结果： Windows Longhorn（Build 4051、4074 等）在 QEMU IA64 模拟环境中 默认可以启动到桌面，无需额外配置。
Build 4033 特别注意事项：

Windows Longhorn Build 4033 的 hal.dll 存在问题，无法使用原版 hal.dll 进行安装。需要将其替换为 Build 4051 fre（零售版） 版本的 hal.dll，才能正常完成安装并进入桌面。

  • 替换方法： 在安装介质或已安装系统的 Windows\System32\ 目录下，将 4033 的 hal.dll 替换为 4051 fre 版本。
  • 获取途径： 从 Build 4051 的 IA64 安装镜像或已安装系统中提取 hal.dll 文件。
  • 注意： 仅 4051 fre 版本适用，chk（检查版） 在此没有进行测试。
测试环境：
  • QEMU 版本：DF4D3110 编译版 / ZZPPAP 编译版
  • 固件：ia64-firmware.bin
  • 磁盘接口：SCSI（默认）
  • CPU：4 核 TCG 多线程模拟
  • 内存：4 GB
已知问题：
  • 时间炸弹： Longhorn 测试版可能有时间限制，如遇到激活或过期提示，请添加 -rtc base=2004-03-27,clock=vm 参数。
  • 性能问题： 由于跨架构运行效率较低，建议关闭宿主机占用较大的程序以提高qemu内系统的运行速度。
Longhorn 推荐启动命令： 
qemu-system-ia64.exe ^
    -machine ia64-vpc,i8042=off,nvram=longhorn.bin ^
    -bios ia64-firmware.bin ^
    -accel tcg,thread=multi ^
    -smp 2 ^
    -m 4G ^
    -nic user,model=e1000 ^
    -drive file=longhorn.vhd,format=vpc ^
    -drive file="4067.iso",media=cdrom,format=raw,readonly=on ^
    -rtc base=2004-03-27,clock=vm ^
    -display gtk

其中 -rtc base=2004-03-27 是 Longhorn 测试版绕过时间炸弹的关键参数。

注意事项

性能警告： TCG 软件模拟效率较低，IA64 模拟尤为明显。启动和安装过程可能需要较长时间，请耐心等待。建议关闭宿主机上其他占用 CPU 的程序。
固件兼容性： 本压缩包已包含 ia64-firmware.bin，如从其他来源获取固件，请确保与 QEMU 版本兼容。如遇到启动问题，尝试更换固件版本。
NVRAM 文件： NVRAM 文件（nvram.bin）用于存储 UEFI 设置。首次运行时会自动生成。如启动异常，可删除并重新生成该文件。
磁盘接口说明：
  • 未指定 if=ide： 磁盘默认为 SCSI 设备。Windows Server 2003 及更早版本、Longhorn 通常可以正常使用 SCSI。
  • 指定 if=ide： 磁盘为 IDE 设备。Windows Server 2008 R2 必须使用 IDE，否则无法启动。
  • 根据目标系统的驱动支持情况，选择合适的接口类型。
网络配置： 使用 -nic user,model=e1000 可让虚拟机通过宿主机的网络访问外部网络。如需桥接网络，可改用 -nic tap,model=e1000（需额外配置）。

故障排除

0x0000007B 蓝屏（无法访问启动设备）

常见于 Windows Server 2008 R2：

  • 检查 -drive 参数是否包含 if=ide（默认是 SCSI，但 2008 R2 需要 IDE）
  • 确认虚拟磁盘格式为 format=vpc
黑屏无法启动

尝试以下操作：

  • 检查 -bios ia64-firmware.bin 文件是否存在且路径正确
  • 删除 NVRAM 文件（nvram.bin）后重新启动
  • 检查 ISO 镜像是否为 IA64 架构可引导
模拟速度极慢

优化建议：

  • 减少 -m 内存分配（如 2G）
  • 确保宿主机有足够的 CPU 资源，关闭其他大型程序
无法从 ISO 引导

检查：

  • ISO 文件是否完整且可引导（建议校验 MD5/SHA）
  • 镜像是否为 IA64 架构（不是 x86/x64/ARM）
  • 在 QEMU 启动后按 Esc 或 F2 进入 UEFI 固件设置，手动选择引导设备
缺少 DLL 错误

如果提示找不到某个 .dll 文件，请确保：

  • 解压时完整保留了所有文件和 lib\、share\ 目录
  • 不要将 qemu-system-ia64.exe 单独移出原目录
  • 必要时将 lib\ 目录添加到系统 PATH 环境变量

说明： 以下为各 Build 在 QEMU IA64 模拟环境下的运行结果，供参考。实际结果可能因 QEMU 版本、固件和宿主机配置而异。

引导修复（Windows Server 2003 / XP 64-Bit Version 2003）

参考来源： 基于 HP Integrity BL860c Server Blade User Service Guide（第 88–91 页）中关于 Microsoft Windows 引导配置的描述，结合 IA64 平台的 EFI 特性整理。

当 Windows 启动项丢失或损坏时，可通过 EFI Shell 手动修复引导记录。以下是完整步骤：

前提条件：
  • 系统已安装 Windows 且 \EFI\Microsoft\WINNT50\ 目录下存在 Boot00nn 文件
  • 当前处于 EFI Shell 环境（从 EFI Boot Manager 选择 EFI Shell 进入）
  • 已确认 Windows 所在的 EFI 系统分区（通常为 fs0: 或 fs2:）
  1. 进入 EFI Shell： 启动 QEMU 后，在 EFI Boot Manager 界面选择 EFI Shell [Built-in]。
  2. 列出所有可引导设备： 在 EFI Shell 提示符下执行： 
    map -r
    找到 Windows 所在的 EFI 系统分区（通常标记为 fsX:，其中 X 为数字）。
  3. 切换到 Windows 所在的 EFI 分区： 
    fs2:
    （将 2 替换为实际分区号）
  4. 确认 Windows 引导文件存在： 
    ls EFI\Microsoft\WINNT50\
    应能看到类似 Boot0001、Boot0002 等文件。
  5. 使用 nvrboot.efi 导入引导项： 
    msutil\nvrboot.efi
    在交互菜单中：
    • 输入 I（Import）导入引导选项
    • 输入引导文件路径，例如：\EFI\Microsoft\WINNT50\Boot0001
    • 按提示完成导入
  6. 验证引导项是否已添加： 
    bcfg boot dump
    检查输出中是否包含 Windows Server 2003 或 Windows Server 2008 R2 相关条目。
  7. （可选）设置 Windows 为默认启动项： 
    bcfg boot mv 2 1
    将 Windows 启动项移至首位（2 为当前编号，1 为目标位置）。
  8. 重启系统： 
    reset
    系统重启后，EFI Boot Manager 应显示 Windows 启动选项。
备选方法： 如果 nvrboot.efi 不可用，可手动添加引导项： 
bcfg boot add 1 \EFI\Microsoft\WINNT50\ia64ldr.efi "Windows Server 2003"

但需注意，ia64ldr.efi 通常不是直接可执行文件，推荐使用 nvrboot.efi 方式导入。

注意事项：
  • 每次更换磁盘或重新安装系统后，都需要重新导入引导项。
  • 如果 EFI\Microsoft\WINNT50\ 目录为空，说明系统未正确安装，请重新安装。
  • 导入后如仍无法引导，检查 -drive 参数中的 if=ide 是否正确（Windows Server 2008 R2 必须使用 IDE）。

RDP 远程桌面转发配置(启用256色可选方案)

功能说明： 通过 QEMU 的端口转发功能，将虚拟机内的 RDP 服务（默认端口 3389）映射到宿主机端口，实现远程桌面连接。
端口转发参数： 
-nic user,model=e1000,hostfwd=tcp::33890-:3389

其中：

  • 33890 — 宿主机端口（可自行修改，但需避免与系统服务冲突）
  • 3389 — 虚拟机内 RDP 服务的默认端口
端口冲突警告： 如果宿主机已开启 RDP 服务（即占用 3389 端口），则不能使用 3389 作为转发接口。请使用其他端口（如示例中的 33890）。

完整启动命令示例（含 RDP 转发）

qemu-system-ia64.exe ^
    -machine ia64-vpc,i8042=off,nvram=nvram.bin ^
    -bios ia64-firmware.bin ^
    -drive file="install.iso",media=cdrom,format=raw,readonly=on ^
    -accel tcg,thread=multi ^
    -smp 4 ^
    -m 4G ^
    -nic user,model=e1000,hostfwd=tcp::33890-:3389 ^
    -drive file=ia64.vhd,if=ide,format=vpc ^
    -display gtk

Windows 系统内配置要求

  1. 启用远程桌面：
    • Windows Server 2003：右键“我的电脑” → 属性 → 远程 → 勾选“启用远程桌面”
    • Windows Server 2008 R2：服务器管理器 → 配置 → 远程桌面设置 → 启用
  2. 为当前用户设置密码： 确保登录账户有密码（空密码无法通过 RDP 认证）。
  3. 确认防火墙放行（可选，通常不需要进行此步）： 在虚拟机内执行以下命令（以管理员身份）： 
    netsh advfirewall firewall add rule name="RDP" dir=in action=allow protocol=TCP localport=3389
    或直接在 Windows 防火墙中添加入站规则（端口 3389）。

连接方法

  1. 启动 QEMU 并等待 Windows 完全启动。
  2. 在宿主机上打开远程桌面连接（mstsc）。
  3. 在“计算机”栏输入：localhost:33890（或您设置的其他宿主机端口）。
  4. 输入虚拟机的用户名和密码，即可连接。
注意事项：
  • QEMU 必须保持运行状态，RDP 连接才能正常使用。
  • 如果连接失败，检查虚拟机内 RDP 服务是否已启动（services.msc 中确认 Remote Desktop Services 状态）。
  • 宿主机端口若被占用，可更换为其他未被使用的端口（如 33891、33900 等）。
