文档：在 WSL2 中使用 WSLg 实现完整桌面环境

通过 WSLg (XWayland) 在 WSL2 中运行 GNOME / KDE / Xfce 等桌面环境 WSL2 WSLg XWayland

准备工作

本教程无需在 Windows 外部安装额外软件（如 VcXsrv 或 xrdp），完全基于 WSLg 实现。
适用版本： 本教程以 Ubuntu 24.04 + GNOME 为例，但同样适用于其他发行版（Debian、Kali 等）和桌面环境（KDE、Xfce、LXDE、Budgie 等）。
系统要求： 本教程对 Windows 11 用户完全兼容。Windows 10 用户虽然也可以尝试，但因 WSLg 支持有限，不保证完整功能。
步骤 1：确保 WSL2 正常运行

确保已安装 WSL2 并能正常运行。如果未安装，参考以下命令：

wsl --install -d Ubuntu
步骤 2：更新系统

在 WSL 终端中运行：

sudo apt update && sudo apt upgrade -y
步骤 3：配置 wsl.conf

确保 /etc/wsl.conf 包含以下内容，如不存在则创建：

[system]
generateResolvConf = false

[network]
generateHosts = false

[interop]
enabled = true
appendWindowsPath = true
提示： 修改完成后，使用 wsl.exe --shutdown 重启 WSL，然后重新打开终端。

安装示例（以 GNOME 为例）

选择并安装元包：

sudo apt install ubuntu-desktop xwayland -y
注意： 安装过程可能需要较长时间，请耐心等待。如果使用 Ubuntu，可以考虑安装 snap-store；如不需要可跳过。
Debian 用户配置区域设置

如果你使用 Debian，需要配置区域设置（Ubuntu 不需要）：

sudo dpkg-reconfigure locales

配置 XWayland

核心步骤： 本步骤的核心是用 XWayland 替换默认的 Xorg，使桌面环境通过 WSLg 正常工作。
步骤 1：创建 systemd 单元修复 /tmp/.X11-unix/

创建新的 systemd 单元：

sudo nano /etc/systemd/system/wslg-fix.service
粘贴以下内容： 
[Unit]
Description=Fix /tmp/.X11-unix permissions for WSLg
Before=display-manager.service
DefaultDependencies=no

[Service]
Type=oneshot
ExecStart=/bin/mount -o remount,exec /tmp/.X11-unix
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
启用服务： 
sudo systemctl enable wslg-fix.service
sudo systemctl start wslg-fix.service
步骤 2：移除 Wayland 引用

编辑 user-runtime-dir@.service 服务：

sudo systemctl edit user-runtime-dir@.service
粘贴以下内容： 
[Service]
ExecStartPre=-/bin/mount -o remount,exec /tmp/.X11-unix
步骤 3：更改默认启动目标

更改默认启动目标，避免每次启动都出现 shell 窗口：

sudo systemctl set-default graphical.target
步骤 4：用 XWayland 替换 Xorg

备份原始 Xorg 脚本：

sudo mv /usr/bin/Xorg /usr/bin/Xorg.original
创建新的 Xorg 脚本： 
sudo nano /usr/bin/Xorg
粘贴以下内容（分辨率可根据需要修改）： 
#!/bin/bash
exec /usr/bin/Xwayland "$@" -geometry 1920x1080
设置权限并创建链接： 
sudo chmod 755 /usr/bin/Xorg
sudo ln -sf /usr/bin/Xorg /usr/bin/Xorg
警告： 系统更新有时会将 Xorg 链接替换为原始版本。如果发生这种情况，只需重复此步骤即可。

配置 GDM 与分辨率

说明： 此步骤用于解决 GDM 和 GNOME 不遵循 Xwayland 分辨率设置的问题，通过 monitors.xml 覆盖。
步骤 1：创建 monitors.xml 
nano ~/.config/monitors.xml
粘贴以下内容（分辨率为 1920x1080，可按需修改）： 
<monitors version="2">
  <configuration>
    <logicalmonitor>
      <x>0</x>
      <y>0</y>
      <scale>1</scale>
      <monitor>
        <monitorspec>
          <connector>XWAYLAND0</connector>
          <vendor>unknown</vendor>
          <product>unknown</product>
        </monitorspec>
        <mode>
          <width>1920</width>
          <height>1080</height>
          <rate>60</rate>
        </mode>
      </monitor>
    </logicalmonitor>
  </configuration>
</monitors>
步骤 2：复制到 GDM 目录 
sudo mkdir -p /var/lib/gdm3/.config
sudo cp ~/.config/monitors.xml /var/lib/gdm3/.config/
sudo chown gdm:gdm /var/lib/gdm3/.config/monitors.xml
sudo chmod 644 /var/lib/gdm3/.config/monitors.xml
步骤 3：重启 WSL

在 Windows 中运行：

wsl.exe --shutdown
重新打开 WSL 终端后，配置生效。

启动桌面环境

启动命令

在 WSL 终端中执行以下命令启动 GDM：

sudo systemctl start gdm
成功： 稍等片刻（通常几秒钟），登录界面应该会出现。登录后即可看到桌面环境。
修改 GDM 行为

编辑 GDM 配置文件，可更改登录行为：

sudo nano /etc/gdm3/custom.conf
取消注释并编辑以下行： 
#WaylandEnable=false
改为： 
WaylandEnable=false

关机与注意事项

重要：一旦启动 WSL 实例，必须执行标准的 Linux 关机操作，否则可能导致 WSL 实例损坏！
关机方法
  • 使用桌面环境菜单中的关机选项
  • 在终端中执行：sudo poweroff

完成后，可安全使用 wsl.exe --terminate 或 wsl.exe --shutdown 关闭 WSL。

故障排除

查看日志

查看 journalctl 日志以排查问题：

journalctl -xe | grep -i xwayland
Debian 用户： 
journalctl -xe | grep -i xwayland
输出中应能看到 Xwayland 生成的命令行及错误信息。
检查 Xorg 脚本是否被替换

如果 Xorg 脚本被系统更新还原，重复“用 XWayland 替换默认 Xorg”部分的步骤即可。

确保 Xorg 为默认显示服务器

确保 Xorg 是默认显示服务器，而非 Xephyr 或 Wayland。

LightDM 用户检查日志

如果使用 LightDM，检查以下日志：

sudo cat /var/log/lightdm/x-0.log
完全重启 WSL

在 Windows 中执行：

wsl.exe --shutdown
提示： 执行前请保存所有未保存的内容。重启后重新打开终端，再次执行 sudo systemctl start gdm。
