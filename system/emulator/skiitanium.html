即用镜像（快捷方案）

预装镜像 (Windows Server 2003 RTM)

此镜像为 5.2.3790.0.srv03_rtm.030324-2048 的已安装版本，可直接进入桌面，省去漫长的安装等待。

  • ⏱ 安装耗时参考：本人测试安装时间约 16.5 小时，此镜像供不想自行安装的用户使用。
  • 📦 镜像文件：ski-zx2000.zip
  • 🛠 部署方式：需要使用 DiskGenius 释放镜像至 8GB 的 .img 虚拟磁盘文件。
  • 📋 包含内容：系统已安装完毕，解压后可直接用于 SKI 仿真器启动。
  • ⚠️ 注意：此镜像为 预装版本，释放后需根据实际环境调整仿真器配置。
Windows Server 2003 RTM IA64

准备安装镜像

准备 ISO 安装镜像

首先，准备好 Windows Itanium 的安装 ISO 镜像。假设我们准备的 ISO 位于 Windows 宿主机中：

D:\6.0.4067.0.idx01.040312-1730_ia64fre_client-professional_retail_en-us-LB1PIFRE_EN.iso
路径说明： 在 WSL 中，Windows 的盘符会挂载到 /mnt/ 目录下。例如 D:\ 盘对应 /mnt/d/。 因此上述 ISO 在 WSL 中的路径为：
/mnt/d/6.0.4067.0.idx01.040312-1730_ia64fre_client-professional_retail_en-us-LB1PIFRE_EN.iso

创建虚拟磁盘

创建 RAW 磁盘镜像

使用 dd 命令创建一个大于等于 4GB 的 RAW 磁盘镜像作为虚拟硬盘：

dd if=/dev/zero of=<path-to-raw-img> bs=1M count=<size-in-mb>
参数说明：
  • if=/dev/zero — 输入文件为零设备，生成全零数据
  • of=<path-to-raw-img> — 输出文件路径，即虚拟磁盘文件
  • bs=1M — 每次写入 1MB 数据块
  • count=<size-in-mb> — 磁盘大小（MB），建议至少 4096（4GB）
示例：

创建一个 8GB 的虚拟磁盘，存放在 /mnt/d/ski-zx2000/ia64.img：

dd if=/dev/zero of=/mnt/d/ski-zx2000/ia64.img bs=1M count=8192

创建 NVRAM

生成 NVRAM 镜像

进入 SKI 仿真器所在目录，使用 mknvram 工具创建 NVRAM 镜像文件：

./mknvram -o nvram.bin
说明： NVRAM（非易失性随机存取存储器）用于存储 UEFI 固件设置，仿真器需要此文件来模拟 Itanium 系统的启动环境。

运行 SKI 仿真器

运行速度可能非常慢！有用户反馈安装耗时超过 24 小时，请做好心理准备。
基本运行命令

使用 bski 启动仿真器，在 ZX2000 模式下运行：

./bski -zx2000 firmware.bin -nvram nvram.bin -zx2000mem <memory-size-in-mb> -cdrom <path-to-iso> -hd <path-to-raw-img>
参数说明：
  • -zx2000 — 使用 ZX2000 模式（Itanium 服务器平台模拟）
  • firmware.bin — 固件文件路径
  • -nvram nvram.bin — NVRAM 镜像路径
  • -zx2000mem — 分配的内存大小（MB），建议 1024 以上
  • -cdrom — ISO 镜像路径
  • -hd — 虚拟硬盘路径
完整示例：

假设 SKI 目录为 /mnt/d/ski-zx2000，ISO 位于 /mnt/d/6.0.4067.0...iso：

./bski -zx2000 firmware.bin -nvram nvram.bin -zx2000mem 1024 -cdrom /mnt/d/6.0.4067.0.idx01.040312-1730_ia64fre_client-professional_retail_en-us-LB1PIFRE_EN.iso -hd /mnt/d/ski-zx2000/ia64.img

注意事项

性能警告： IA-64 仿真效率极低，安装过程可能需要数小时甚至数天。已知有用户安装 Windows Itanium 耗时超过 24 小时，请耐心等待。
磁盘空间： 确保宿主机有足够的磁盘空间存放虚拟磁盘文件（至少 4GB，推荐 8GB 以上）和 ISO 镜像。
路径格式： 在 WSL 中访问 Windows 文件时，务必使用 /mnt/<盘符>/ 格式，例如 /mnt/d/。盘符必须小写。

故障排除

黑屏无法启动

如果启动时出现黑屏无法启动：

  1. 尝试删除 nvram.bin.bmc 文件
  2. 如果仍然无法启动，删除 nvram.bin 和 nvram.bin.bmc 两个文件，然后重新生成 NVRAM 镜像

删除 .bmc 文件是无害的，但删除 nvram.bin 会导致所有 EFI 设置丢失。

重新生成 NVRAM

如果 NVRAM 损坏或需要重置，重新运行以下命令：

./mknvram -o nvram.bin
检查文件完整性

确保以下文件存在且完整：

  • bski — 主仿真器程序（可执行）
  • mknvram — NVRAM 生成工具（可执行）
  • firmware.bin — IA64 固件文件
  • nvram.bin — 生成的 NVRAM 镜像

Windows IA64 引导修复

适用场景： 当 Windows Itanium 系统无法正常启动、引导项丢失或损坏时，可通过以下步骤修复 EFI 引导。

8.1 添加 Windows 引导项

说明： 如果 Windows 引导项从 EFI 启动菜单中丢失，需要从 EFI Shell 手动导入。
  1. 步骤 1：进入 EFI Shell

    在系统启动时进入 EFI Boot Manager，选择 EFI Shell 进入命令行环境。

  2. 步骤 2：定位 EFI 系统分区

    使用 map -r 命令列出所有可用的文件系统，找到包含 Windows 引导文件的 EFI 分区（通常为 fs0: 或 fs1:）。

    Shell> map -r
Device mapping table
fs0 : Acpi(...)/Pci(...)/Scsi(...)/HD(Part1,...)
fs1 : Acpi(...)/Pci(...)/Scsi(...)/HD(Part1,...)
  3. 步骤 3：进入 Windows 引导分区

    切换到 Windows 所在的 EFI 系统分区：

    Shell> fs0:
fs0:\>
  4. 步骤 4：确认 Windows 引导文件存在

    检查 \EFI\Microsoft\WINNT50\ 目录下的引导文件：

    fs0:\> ls EFI\Microsoft\WINNT50
Directory of: fs0:\EFI\Microsoft\WINNT50
09/18/03  11:58a  <DIR>    1,024
09/18/03  11:58a  <DIR>    1,024
12/18/03  08:16a         354  Boot0001
1 File(s)       354 bytes
2 Dir(s)
    注意： Boot0001 是 Windows 的引导选项文件，文件名可能因版本而异（如 Boot00nn）。
  5. 步骤 5：导入 Windows 引导项

    使用 nvrboot.efi 工具将 Windows 引导项导入到 NVRAM：

    fs0:\> msutil\nvrboot

NVRBoot: OS Boot Options Maintenance Tool [Version 5.2.3683]

1.  SUSE SLES 10
2.  HP-UX Primary Boot: 0/0/1/0/0.2.0 *
3.  Windows Server 2003, Datacenter
4.  EFI Shell [Built-in]
* = Windows OS boot option

(D)isplay  (M)odify  (C)opy  E(x)port  (I)mport  (E)rase  (P)ush  (H)elp  (Q)uit

Select> I
Enter IMPORT file path: \EFI\Microsoft\WINNT50\Boot0001
Imported Boot Options from file: \EFI\Microsoft\WINNT50\Boot0001
Press enter to continue
    参数说明：
    • I — Import，导入引导选项
    • 文件路径 — Windows 引导文件在 EFI 分区中的完整路径
  6. 步骤 6：退出并重启

    输入 Q 退出 nvrboot 工具，然后执行 reset 重启系统。

    Select> Q
Shell> reset

8.2 使用 bcfg 命令添加引导项（备用方法）

说明： 如果 nvrboot 工具不可用，可以使用 EFI Shell 内置的 bcfg 命令手动添加引导项。
  1. 步骤 1：确认引导文件路径

    在 EFI 系统分区中确认 Windows 引导加载器的完整路径：

    fs0:\> ls \EFI\Microsoft\WINNT50\*.efi
ia64ldr.efi
  2. 步骤 2：使用 bcfg 添加引导项

    将 Windows 引导加载器添加到引导选项列表：

    Shell> bcfg boot add 1 \EFI\Microsoft\WINNT50\ia64ldr.efi "Windows Server 2003"
    参数说明：
    • 1 — 引导项在列表中的位置
    • \EFI\Microsoft\WINNT50\ia64ldr.efi — 引导加载器路径
    • "Windows Server 2003" — 在 EFI Boot Manager 中显示的名称
  3. 步骤 3：验证引导项

    查看当前引导选项列表，确认 Windows 已添加：

    Shell> bcfg boot dump
Option 00: EFI Shell [Built-in]
Option 01: Windows Server 2003
Option 02: HP-UX Primary Boot: 0/0/1/0/0.2.0
  4. 步骤 4：设置自动启动超时

    设置引导超时时间，让系统自动引导：

    Shell> autoboot on
Shell> autoboot time 10

8.3 清除 NVRAM 重置

警告： 此操作将清除所有 NVRAM 设置，包括所有引导选项、EFI 配置和密码。仅在无其他方案时使用。
  1. 步骤 1：进入 EFI Shell

    重启系统并进入 EFI Shell。

  2. 步骤 2：执行 NVRAM 清除 
    Shell> default clear
Are you sure you want to clear all NVRAM settings? [y/N] y
Shell> reset
    说明： 系统重启后，EFI NVRAM 将恢复出厂设置，需要重新配置引导项。

8.4 常见问题排查

问题 1：无法找到 EFI 系统分区

执行 map -r 后看不到任何 fsX: 设备：

  • 检查硬盘是否连接正常
  • 确认硬盘包含 EFI 系统分区（FAT32 格式）
  • 尝试 map -r 重新扫描设备
问题 2：引导文件缺失

\EFI\Microsoft\WINNT50\ 目录为空或不存在：

  • 从 Windows 安装介质复制 ia64ldr.efi 和 Boot00nn 文件
  • 重新安装 Windows 以恢复引导文件
问题 3：引导项添加后仍无法启动

添加引导项后选择 Windows 但无法进入系统：

  • 检查 boot.ini 或 BCD 配置是否正确
  • 确认 Windows 系统盘是否包含完整的 \Windows\System32 目录
  • 尝试使用 Windows 安装介质的修复功能
